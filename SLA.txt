============================================================
1. Amazon Compute SLA (информационная система: облачные ВМ Amazon EC2)
Источник: https://aws.amazon.com/compute/sla/
Актуальность: редакция от 25 мая 2022 г.
============================================================

Предмет. Соглашение об уровне сервиса для Amazon Elastic Compute Cloud
(EC2) — облачной ИС для запуска виртуальных серверов. Действует отдельно
для каждого аккаунта AWS.

Два уровня обязательств.

  A) Region-Level SLA (несколько зон доступности)
     Если все работающие инстансы размещены одновременно минимум в двух
     Availability Zones одного региона, AWS обязуется обеспечить
     Monthly Uptime не ниже 99,99% за расчётный месяц.

     Компенсация (service credit) от месячного счёта за EC2 в регионе:
       • меньше 99,99%, но ≥ 99,0%  →  10%
       • меньше 99,0%,  но ≥ 95,0%  →  30%
       • меньше 95,0%               → 100%

  B) Instance-Level SLA (один инстанс)
     Для отдельного инстанса целевой uptime — не ниже 99,5% в месяц.

     Компенсация:
       • меньше 99,5%, но ≥ 99,0%  →  10%
       • меньше 99,0%,  но ≥ 95,0%  →  30%
       • меньше 95,0%               → 100%

     Дополнительно: час, в котором инстанс был недоступен более 6 минут,
     не тарифицируется автоматически (отдельный запрос не нужен).

Как считается доступность.
  Monthly Uptime = 100% минус доля минут месяца, когда сервис был
  в состоянии Unavailability (нет внешней связности). Для регионального
  SLA «недоступность» — когда ВСЕ инстансы в двух и более AZ региона
  одновременно без внешней связности.

Как получить кредит.
  Нужно открыть обращение в AWS Support Center до конца второго
  расчётного цикла после инцидента. В заявке: даты/время, регион,
  ID ресурсов, логи. Кредиты идут в счёт будущих платежей за EC2,
  не переводятся на другой аккаунт, минимум — $1.

Исключения (SLA не действует):
  • форс-мажор, проблемы интернета за границей ответственности AWS;
  • действия/бездействие клиента (в т.ч. игнор сигналов о здоровье ресурса);
  • оборудование и ПО клиента;
  • приостановка или блокировка аккаунта по договору.


============================================================
2. GitHub Enterprise / Online Services SLA
   (информационная система: платформа разработки GitHub)
Источники:
  https://docs.github.com/en/site-policy/site-policy-deprecated/github-enterprise-service-level-agreement
  https://github.com/customer-terms/github-online-services-sla
Актуальность: публичные условия GitHub (Enterprise Cloud / Online Services)
============================================================

Предмет. SLA для облачной ИС GitHub (репозитории, Issues, Pull Requests,
Git-операции, API, Webhooks, Pages, Actions). Целевой уровень доступности
считается за календарный квартал, а не за месяц.

Обязательство.
  GitHub гарантирует Uptime не ниже 99,9% за квартал для покрываемых
  функций сервиса. Текущий статус: https://www.githubstatus.com/

Что считается простоем (Downtime).
  Минута, в которую доля ошибок превышает 5%, либо сервис недоступен
  по данным внутренней и внешней мониторинга GitHub.
  Формула: Uptime = (минуты квартала − простой) / минуты квартала.

Компенсация (service credits) от оплаты за квартал:
  • uptime ≤ 99,9% и > 99,0%  →  10%
  • uptime < 99,0%            →  25%
  (в актуальном Online Services SLA также есть ступень 5% при
   99,5% ≤ uptime < 99,9%)

Как получить кредит.
  Письменный запрос в GitHub Support в течение 30 дней после окончания
  квартала. Кредит — на счёт клиента (не «живые» деньги), максимум
  90 дней оплаченного сервиса за квартал. Нужно не иметь просроченных
  счетов. Это единственное средство защиты при нарушении SLA.

Исключения:
  • действия, ошибки или нарушение договора со стороны клиента;
  • сбой интернет-канала клиента;
  • форс-мажор и факторы вне разумного контроля GitHub;
  • оборудование и технологии клиента;
  • плановые работы (Scheduled Downtime) в актуальной редакции
    Online Services SLA не входят в простой.
